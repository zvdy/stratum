# stratum

<p align="center"><em>Static PostgreSQL migrations → Mermaid ERD — no database, no cgo.</em></p>

`stratum` is a Go CLI that **statically** parses PostgreSQL migration `.sql`
files and generates a [Mermaid](https://mermaid.js.org/) ERD embedded in a
Markdown document. It opens **no database connection** and makes **no network
calls** — every fact in the diagram is derived from the migration files
themselves, so it runs fully offline (e.g. in a GitHub Actions runner).

It works by replaying your migrations in order against an in-memory schema
model and rendering the result. Parsing uses a small, **hand-written pure-Go**
SQL DDL parser (no cgo, no third-party parser) that models the subset of
PostgreSQL DDL an ERD needs and defensively skips everything else.

!!! tip "See it in action"
    The [live example](example.md) page on this site is generated by stratum
    itself, from this repository's own test migrations, on every deploy.

## Quick start

```bash
go build -o stratum ./cmd/stratum
./stratum --migrations-path db/migrations --output SCHEMA.md
```

Or in CI, as a GitHub Action:

```yaml
- uses: actions/checkout@v4
- uses: zvdy/stratum@v1
  with:
    migrations-path: db/migrations
    output: SCHEMA.md
```

## Why static?

- **No database to spin up** — nothing to provision, seed, or tear down in CI.
- **No drivers, no cgo** — a single static binary; `CGO_ENABLED=0` just works.
- **Deterministic** — the same migrations always produce byte-identical output,
  which is what makes the [`--check` CI gate](usage.md#keeping-docs-fresh-in-ci)
  possible.
